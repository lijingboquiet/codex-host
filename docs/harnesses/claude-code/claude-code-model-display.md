# Claude Code model display

Claude Code selects the model itself: the "Default" catalog row sends no model to the SDK, so the CLI resolves whatever the user's settings configure (a settings default, an alias target, or a relayed model). The selectable Ref is therefore not evidence of the model actually in use. The runtime reports that model as `context.model` in its context readback and as `lastRequestUsage.model` on each root assistant message.

The Adapter surfaces the resolved model as `HarnessSessionState.resolvedModelLabel`, which Host projects to the picker. It is captured from the normal message flow — `#applyLatestRequestUsage`, driven by the native `message.completed` event — so the label updates during a turn without opening the usage popover and without any extra RPC. The lazy `getContextUsage` path (usage popover only) captures the same label when it runs, but is not required for the label to appear.

Subagents never overwrite the root label. Native subagent messages carry `parent_tool_use_id`, so `ClaudeNativeTurnAccumulator` does not emit `message.completed` for them (`native-message.ts`); only root messages produce the usage event that feeds the label. A subagent model (e.g. `CLAUDE_CODE_SUBAGENT_MODEL`) is never observed as the session's resolved model.

A confirmed model switch invalidates the previous resolution. `#selectModel` success bumps `#modelSelectionRevision` and clears `#resolvedModelLabel`; each Turn stamps the revision it started under. A late root message from the previous model is applied for token usage but is trusted for the label only while its stamp still matches the current revision, so a switch is never overwritten by a stale message. A failed switch does not bump the revision and keeps the current label. Thinking and permission-mode changes do not touch the revision or the label. After a switch the label stays unknown until the new model confirms itself — brief unknown is preferred over a wrong model. The revision is dedicated: reusing `#usageGeneration` would be wrong because thinking, permission, and new-turn boundaries all increment it.

In the renderer picker the trigger keeps the selected alias label as the primary text. The secondary span is width-capped, so it shows the short Thinking label (e.g. "Extra High") inline and never lets a long resolved model clip it; when Thinking is unavailable the resolved model takes the inline slot instead. The complete "resolved model · thinking" composition is always available through the trigger and secondary-span `title` and the `aria-label`, so the real model stays inspectable regardless of the inline width.

Personal defaults (a specific model, `xhigh` thinking) belong in the user's own `settings.json` and the renderer per-Harness preference (`codexhost.new-thread-preference.v1`), not in shared code. Do not hardcode a personal model or effort level into the Adapter or contracts.
